# 企业智能物资采购系统 - 快速开发计划

## Context
用户要求基于"企业智能物资采购系统需求汇总.txt"制定快速开发计划。这是一个全新的智能采购管理系统项目，需要实现供应商管理、采购流程、库存控制、财务核算和AI聊天助手等功能。

### 当前项目状态分析
- **基础结构**: 仅有基础Python包结构（pyproject.toml, uv.lock），简单的main.py入口文件
- **需求文档**: 详细的中文需求文档（7406字）定义了完整功能和技术栈
- **技术栈要求**: Python 3.11 + FastAPI + PostgreSQL 18 + Vue 3 + Tailwind CSS 4 + pydantic_ai
- **界面布局**: 左中右三栏布局（左侧菜单、中间主视图、右侧AI聊天框）
- **AI约束**: AI聊天仅支持文本和只读数据库查询，无文件上传功能

### 发现的关键信息
1. **项目成熟度**: 0/10 - 全新项目，需要从头构建
2. **核心功能模块**: 7大模块（供应商、采购、库存、财务、分析、报表、AI聊天）
3. **用户角色**: 4种角色（管理员、部门领导、管理层、员工）
4. **非功能需求**: 性能、安全、兼容性、可靠性要求明确
5. **开发环境**: 使用uv包管理器，Python 3.11

目标：制定一个高效的开发计划，快速构建可运行的MVP版本，优先实现核心采购流程和AI聊天功能。

## 计划概述

### 5周MVP交付计划
1. **第1周**: 基础架构搭建 - 建立完整的开发环境、项目骨架和基础服务
2. **第2-3周**: 核心模块开发 - 实现P0优先级功能模块（用户管理、供应商管理、采购管理）
3. **第4周**: P1模块集成 - 实现库存管理和AI聊天功能
4. **第5周**: MVP完善与部署 - 系统集成、测试和部署准备

### 核心优先级策略
- **P0（必须完成）**: 用户权限系统、供应商管理、采购核心流程
- **P1（MVP重要功能）**: 库存管理、AI文本聊天+只读查询
- **P2（后续迭代）**: 财务管理、高级分析、自定义报表

## 风险评估与缓解措施

### 技术风险
1. **数据库性能问题**
   - 风险：采购数据量大时查询慢
   - 缓解：初始设计考虑索引优化，核心表添加适当索引

2. **AI集成复杂性**
   - 风险：pydantic_ai学习曲线，只读查询权限控制复杂
   - 缓解：第一阶段实现基础文本聊天，第二阶段增加只读查询，使用中间层严格限制SQL操作

3. **权限系统漏洞**
   - 风险：RBAC实现不完整导致越权访问
   - 缓解：基于角色的权限装饰器统一验证，自动化权限测试用例

### 项目管理风险
1. **范围蔓延**
   - 风险：需求不断增加影响MVP交付
   - 缓解：严格按优先级执行，P2需求放入后续迭代

2. **技术债务累积**
   - 风险：快速开发导致代码质量下降
   - 缓解：基础代码规范，关键模块单元测试

```bash
# 数据库验证
uv run alembic upgrade head  # 应成功应用数据库迁移
uv run alembic revision --autogenerate -m "test"  # 应成功生成新迁移
```

### 端到端测试场景
1. **用户注册登录流程**
   - 新用户注册 → 邮箱验证 → 登录 → 访问权限控制页面

2. **采购完整流程**
   - 员工提交采购需求 → 部门领导审批 → 生成采购订单 → 供应商确认 → 入库登记

3. **AI聊天功能**
   - 文本聊天：用户提问 → AI响应
   - 数据查询：用户查询"最近的采购订单" → AI返回只读查询结果

4. **权限验证**
   - 不同角色用户登录 → 验证可见功能和数据范围符合权限设置

2. **核心功能**：4种角色用户可登录，供应商完整CRUD操作，采购流程完整走通
